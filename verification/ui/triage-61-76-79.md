## Issue 61: iOS Heading Contrast

- Tested current theme with body classes `theme-light is-ios is-mobile is-phone` in Playwright WebKit 18.4 (build 2158) and WebKit 26.6 (build 2359).
- Both engines compute H1 and H4 text as `oklch(0.975 0.03 202.509995)` on the default dark teal background, and dark text at lightness 0.3 for H2/H3/H5/H6. Internal heading links follow the same contrast.
- `61-before-webkit18.png` and `61-before-webkit.png` show those current results. Matching JSON files contain all six heading and link colours.
- No iPhone/iPad hardware or native iOS Obsidian instance was available. These Windows WebKit fixtures cannot establish native iOS correctness or rule out an older OS/rendering/configuration issue.
- No code change was made because the report did not reproduce in either tested WebKit generation. The CSS `-infinity` expression alone is not evidence of this bug; both tested engines evaluate it correctly.

## Issue 79: Translucent Window Colours

- The issue screenshot's grey sidebars are consistent with Obsidian's `.is-translucent:not(.is-fullscreen)` CSS path. This is a reproduction hypothesis supported by the cascade, not confirmation of the reporter's setting.
- Exact test classes: `theme-dark mod-macos ssopt-col-base-lightness-d-vivid ssopt-col-base-tone-d-hagia-sophia ssopt-col-accent-d-nebula`, then vary `is-translucent` and `is-fullscreen`.
- In the actual Obsidian 1.13.7 Windows renderer, the opaque window and the fullscreen-class case paint the titlebar and sidebars with `oklch(0.26 0.05 295)`.
- Adding `is-translucent` without fullscreen makes those sidebars transparent via Obsidian's `!important` overrides; titlebar/app-container use `oklch(0 0 none / 0.6)` from the native `--workspace-background-translucent` variable.
- The theme does not define that translucent-background variable. Obsidian intentionally excludes this rendering path in fullscreen, explaining the mode-specific difference.
- Evidence: `79-class-cascade-results.json` and `79-{opaque-window,translucent-window,translucent-fullscreen}-real-renderer.png`.
- These screenshots use a real Windows Obsidian renderer with macOS CSS classes. Native macOS vibrancy/background compositing was not available and is not simulated.
- A bounded fix is available on branch `codex-willemstad-79-translucent-colors`: map the native translucent tint to the selected base palette, or opposite palette for cross-colour UI, while retaining the 60% opacity and transparent child surfaces.
- `79-tint-results.json` records 72 real-renderer before/after cases across light/dark, Hagia Sophia/Tropical Lagoon, normal/inverted/imported cross-colour modes, and opaque/translucent/fullscreen classes. All assert the expected palette tint, unchanged opacity, transparent children, and unchanged opaque/fullscreen backgrounds.
- The new screenshots `79-{before,after}-tint-{light,dark}-real-renderer.png` are renderer-level evidence. Native macOS confirmation remains outstanding; preserving translucency means the final appearance can still differ from opaque/fullscreen rendering according to the user's desktop backdrop.
